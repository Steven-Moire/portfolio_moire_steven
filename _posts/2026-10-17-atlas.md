# atlas: AI/ML Project Template & Claude Code Setup
**Personal project · Private repository**

I built atlas from a simple observation. At the company where I did my apprenticeship, we already had repositories with templates, and that saves precious time. For most of my data science projects, I start again from the same base: this service, wired to that one, a dashboard to check certain points, a CI/CD pipeline with specific checks, and so on. Having a ready-to-use template lets me go straight to the points that matter most instead of the setup. It also keeps my projects consistent with each other.

---

## Service templates

- 7 service templates, FastAPI and Flask: LLM gateway, ML inference, LLM inference, document ingestion, human review app, dashboard, microservice skeleton. Each has its own Dockerfile and runs on its own.
- Services only talk over versioned HTTP (`/v1/`). Allowed calls are declared in a service graph, and an integration test checks the real network against it.
- LLM gateway: requests stay on a local model by default, and a "zero cloud" mode makes any external call impossible.
- Blocking CI checks: ruff, mypy strict, coverage ≥ 70%, file length by role, shellcheck and bats for shell scripts.
- Supply chain: hash-locked dependencies, GitHub Actions pinned by SHA, minimal CI permissions, Bandit, Semgrep and Gitleaks scans with no global exemption.
- Kubernetes: one shared generic Helm chart (Deployment, or CronJob for scheduled jobs), validated in CI without a cluster. Prometheus metrics and JSON logs on every service, with a local Grafana to check them.
- `/start-project` asks the questions that shape the architecture (sensitive data, GPU, local or API LLM, scheduled agent), then configures the project.

---

## Claude Code setup

### Built on open source, curated

The base is [Everything Claude Code](https://github.com/affaan-m/everything-claude-code) (MIT, Affaan Mustafa), a large community collection. I cut it down to what I actually use, then built on top.

| Component | Installed | What for |
|---|---|---|
| Agents | 28 | Planner, architect, TDD guide, security / Python / FastAPI reviewers… |
| Skills | 101 | Patterns and workflows loaded on demand |
| Commands | 77 | `/plan`, `/code-review`, `/quality-gate`… |
| Rules | 21 | Always-loaded coding, testing and security rules |

Licences are kept apart: the ECC infrastructure stays under its author's MIT licence, my own templates under mine. The merge is documented in a decision record.

### A behavioural contract

Seven rules at the top of every `CLAUDE.md`, adapted from the widely shared "4 rules" for AI agents to multi-service projects:

| Generic advice | My version |
|---|---|
| Ask when uncertain | **Scope first**: list the services impacted, wait for confirmation if more than one |
| Write minimal code | **Service boundaries are red lines**: HTTP `/v1/` only, never a cross-service import |
| Touch only what you must | **No drive-by refactoring**: flag a cleanup, never apply it silently |
| Define done | **Done = objective criteria**: lint, green tests, coverage, clean `git status` |
| *(missing)* | **Read the current code, never memory** |
| *(missing)* | **Anything set aside is tracked** and brought back until I decide to drop it |

### Guardrails as hooks

- Client-residue guard: blocks any `git commit` / `git push` whose diff contains a confidential term. It exists because of a real incident: a client identifier slipped into a committed script right after a sanitisation pass. Two lists are merged: past clients live on the machine only, never in a repo; the current project has its own list. Covered by tests.
- Naming guard: warns when a Python file's name does not state its role (`_router`, `_service`, `_utils`…), each role having a line budget.
- Permissions: force-push denied; push, reset, rebase and `.env` edits always ask a human first.

### Rules and rituals

- Static-analysis rules written after a real scan: cognitive complexity ≤ 15, nesting ≤ 4, mandatory docstrings, and never "fix" a finding by tricking the scanner.
- Import discipline rules against cascading dependencies between layers.
- `/friday`: weekly audit of quality, security, debt and docs, measured and prioritised, never fixed on the spot. `/monday` turns it into a week plan. `/passation` writes a dated handover document.
- Decisions are recorded as ADRs.

## What I learned

A lot, really, because I ask Claude to build a lot of things. But when a point escapes me, I take the time to learn and build up my skills. And I reread every one of my files: if there is a passage I don't understand, same thing. I'm not just sitting behind my screen waiting for it to happen; I try to understand what my agent is doing. That is also how I developed skills and guardrails for Claude.

# atlas : template de projets IA/ML et configuration Claude Code
**Projet personnel · Dépôt privé**

J'ai voulu construire atlas en partant d'un constat simple. Dans l'entreprise où j'ai fait mon alternance, on avait déjà des dépôts avec des templates, et ça permet de gagner un temps précieux. Pour la plupart de mes projets en data science, je repars sur une même base : tel service, branché avec un autre, un dashboard pour vérifier certains points, une CI/CD avec des points précis, etc. Avoir un template clé en main me permet d'attaquer directement les points les plus importants, et pas le setup. Cela me permet aussi d'avoir une cohérence entre chacun de mes projets.

---

## Templates de services

- 7 templates de services, FastAPI et Flask : passerelle LLM, inférence ML, inférence LLM, ingestion de documents, application de relecture humaine, dashboard, squelette de microservice. Chacun a son Dockerfile et se lance seul.
- Les services ne communiquent que par HTTP versionné (`/v1/`). Les appels autorisés sont déclarés dans un graphe de services, et un test d'intégration vérifie que le réseau réel le respecte.
- Passerelle LLM : une requête reste par défaut sur un modèle local, et un mode « zéro cloud » rend tout appel externe impossible.
- Contrôles bloquants en CI : ruff, mypy strict, couverture ≥ 70 %, longueur des fichiers selon leur rôle, shellcheck et bats pour les scripts shell.
- Chaîne d'approvisionnement : dépendances verrouillées avec hash, actions GitHub épinglées par SHA, permissions CI minimales, scans Bandit, Semgrep et Gitleaks sans dérogation globale.
- Kubernetes : un chart Helm générique partagé (Deployment, ou CronJob pour les tâches planifiées), validé en CI sans cluster. Métriques Prometheus et logs JSON sur chaque service, avec un Grafana local pour les vérifier.
- `/start-project` pose les questions qui déterminent l'architecture (données sensibles, GPU, LLM local ou API, agent planifié), puis configure le projet.

---

## Configuration Claude Code

### Une base open source, curée

La base est [Everything Claude Code](https://github.com/affaan-m/everything-claude-code) (MIT, Affaan Mustafa), une grande collection communautaire. Je l'ai réduite à ce que j'utilise vraiment, puis j'ai construit par-dessus.

| Composant | Installés | Pour quoi |
|---|---|---|
| Agents | 28 | Planner, architecte, guide TDD, reviewers sécurité / Python / FastAPI… |
| Skills | 101 | Patterns et workflows chargés à la demande |
| Commandes | 77 | `/plan`, `/code-review`, `/quality-gate`… |
| Règles | 21 | Règles de code, tests et sécurité chargées en permanence |

Les licences restent séparées : l'infrastructure ECC sous la licence MIT de son auteur, mes templates sous la mienne. La fusion est documentée dans un enregistrement de décision.

### Un contrat comportemental

Sept règles en tête de chaque `CLAUDE.md`, adaptées des « 4 règles » largement partagées pour les agents IA aux projets multi-services :

| Conseil générique | Ma version |
|---|---|
| Demander en cas de doute | **Périmètre d'abord** : lister les services impactés, attendre confirmation si plus d'un |
| Écrire le minimum de code | **Les frontières de service sont des lignes rouges** : HTTP `/v1/` uniquement, jamais d'import inter-services |
| Ne toucher que le nécessaire | **Zéro refactoring passant** : signaler un nettoyage, ne jamais l'appliquer en silence |
| Définir « terminé » | **Terminé = critères objectifs** : lint, tests verts, couverture, `git status` propre |
| *(absent)* | **Lire le code courant, jamais la mémoire** |
| *(absent)* | **Tout ce qui est mis de côté est tracé** et reproposé jusqu'à ce que je décide de l'abandonner |

### Des garde-fous en hooks

- Garde anti-résidus client : bloque tout `git commit` / `git push` dont le diff contient un terme confidentiel. Il existe à cause d'un vrai incident : un identifiant client s'est glissé dans un script committé juste après un chantier de sanitisation. Deux listes fusionnées : les anciens clients vivent uniquement sur la machine, jamais dans un dépôt ; le projet en cours a sa propre liste. Couvert par des tests.
- Garde de nommage : avertit quand le nom d'un fichier Python n'annonce pas son rôle (`_router`, `_service`, `_utils`…), chaque rôle ayant un budget de lignes.
- Permissions : force-push interdit ; push, reset, rebase et modification du `.env` demandent toujours l'accord d'un humain.

### Règles et rituels

- Règles d'analyse statique écrites après un vrai scan : complexité cognitive ≤ 15, imbrication ≤ 4, docstrings obligatoires, et ne jamais « corriger » une alerte en trompant le scanner.
- Règles de discipline d'import contre les dépendances en cascade entre couches.
- `/friday` : audit hebdomadaire de la qualité, de la sécurité, de la dette et de la doc, mesuré et priorisé, jamais corrigé dans la foulée. `/monday` en fait un plan de semaine. `/passation` produit un document de passation daté.
- Les décisions sont tracées en ADR.

## Ce que j'en retiens

Beaucoup, en soi, parce que je demande à Claude de construire beaucoup de choses. Sauf que si un point m'échappe, je prends le temps de me former et de monter en compétence. Et je relis chacun de mes fichiers : s'il y a un passage que je ne comprends pas, c'est pareil. Je ne suis pas juste derrière mon écran à attendre que ça se passe, j'essaie de comprendre ce que fait mon agent. C'est aussi comme ça que j'ai développé des skills et des garde-fous pour Claude.
